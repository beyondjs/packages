# Type browsing fixtures

Used by [tests/types](../README.md), whose harness ([support/served.mjs](../support/served.mjs)) copies them into a unique temporary directory and never writes them. Nothing here is compiled by Packages' own build: `beyond.json` of the repository names only its root package.

## Workspace (`workspace/`)

`beyond.json` declares `runtime` (the development runtime, which the harness copies in), `app` and `packaged`. `package-lock.json` records where each installed package came from: the npm registry, except `git-lib`, installed from Git.

| Package | Modules | What it is for |
| --- | --- | --- |
| `@types-fixture/app` 1.0.0, `ts` bundler on the development runtime | `./main` (`web`), `./text` (`node`, `web`), `./broken` (`web`), `./theme` (a stylesheet) | `./main` imports a type of `typed-lib`, a value of `conditioned` and `./text`, and its public declaration keeps all three as bare references. `./broken` does not check on purpose (line 5). `./theme` is a style module: it has no declaration |
| `@types-fixture/packaged` 1.0.0, `esbuild` bundler | `./main` (`web`, `node`) | Typed source in the esbuild packaging mode, whose bundler has no `types` conditional: `DECLARATION_PRODUCER_MISSING` |
| `@beyond-js/local-2026` (copied as `runtime/`) | Its exported modules, `esbuild` bundler | The development runtime's `bundle`, which has no producer of declarations either |

## Installed packages (`installed/`, `nested/`)

`installed/` becomes the `node_modules` of the workspace, and `nested/conditioned/` becomes `node_modules/conditioned/node_modules`, which is the only change of layout: no `node_modules` directory is checked in.

| Package | What it declares | Expected answer |
| --- | --- | --- |
| `typed-lib` 1.0.0 | `types: ./index.d.ts` | `package`, `index.d.ts`, from the workspace |
| `typed-lib` 2.0.0 (under `conditioned`) | `typings: ./index.d.ts` | What `conditioned`'s declaration references, followed from `conditioned` |
| `conditioned` 2.0.0 | `exports`: `.` with an `import` target that has no declaration beside it, then `types`; `./extra` with an `import` target without a declaration, then a `default` one with it; `./hidden` null; `./features/*` | `dist/index.d.ts`, `dist/extra.d.ts`, `dist/features/alpha.d.ts`; `./hidden` and `./missing` are `DECLARATION_NOT_FOUND` |
| `untyped` 1.0.0 and `@types/untyped` | JavaScript only, typed by its `@types` package, which references `typed-lib` | `types-package`, `index.d.ts` |
| `javascript-only` 1.0.0 | JavaScript only, no `@types` package | `DECLARATION_NOT_FOUND` |
| `escaping` 1.0.0 | `types: ../typed-lib/index.d.ts`, outside the package | `TYPES_ACCESS` |
| `linked` 1.0.0 | `types: ./index.d.ts`, which the harness replaces with a symbolic link to the workspace's `beyond.json` | `TYPES_ACCESS`, and the linked file is not answered |
| `git-lib` 1.0.0 | `types: ./index.d.ts`, installed from Git as the lockfile records | `TYPES_UNSUPPORTED` |
| `source-lib` 1.0.0 | `exports: ./main → ./main/index.ts`, a TypeScript source | `package`, `form: source` |
| `subpaths` 1.0.0 | No `exports`; `types: ./lib/index` without an extension, `single.d.ts`, `lib/parts/index.d.ts` | `lib/index.d.ts`, `single.d.ts`, `lib/parts/index.d.ts` |

## Generated by the harness

`huge` 1.0.0 is written into the copy's `node_modules` by the harness, because its size is the behavior under test: `types: ./index.d.ts`, a declaration of `Served.HUGE` bytes (1 MiB and 4 KiB), one exported constant per line, past the 1 MiB the route reads. It is `TYPES_UNSUPPORTED` with `size` and `limit`. Inspect it by running the harness and reading `node_modules/huge/index.d.ts` of the copy before it is removed.
