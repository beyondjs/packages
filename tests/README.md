# Packages tests: index

Every validation of this repository, where it runs from and what it needs. `tests/` holds integration validations of the Packages implementation, one directory per group with its own entry (`index.mjs`) and report (`PASS`/`FAIL` per step, `N/N passed` at the end, exit code 1 on a failure). They are numbered steps rather than `*.test.mjs` files because each group drives one Engine-served implementation, a live service or a browser through one ordered scenario, and its README says what each step establishes. Contract tests of the service, the bootstrap and the development contract use Node's test runner and are listed [at the end](#nodetest-suites).

Unless a group says otherwise, a group runs from the Packages directory under BEE Node, with the bootstrap Engine serving this implementation, as described in [the stage-1 prerequisites](stage-1/README.md):

```sh
cd "$PACKAGES_DIR"
BEE_URL=http://localhost:1112 [WATCHERS_URL=http://localhost:1120] \
  node --import "$BEE_NODE_DIR/register.mjs" tests/<group>/index.mjs
```

Behavior of an installed toolchain is accepted by the command line's acceptance, never by these groups: they run against a checkout served by Engine.

## Layout

- `tests/<group>/fixtures/` (or `fixture/` in the groups that predate the suite rule) holds permanent source examples: packages, modules and assets as ordinary files. A harness copies them into a unique temporary directory, applies any narrow substitution there, and never writes the checked-in files. Each group's README describes its fixtures, their entry modules and their intentionally invalid cases.
- The `.mjs` files beside them are the harness and the assertions. Sources that stay generated or inline (size stress, deliberately malformed inputs, short edits) are listed with their reason in the group's README.
- Fixtures are not packages of this repository: `beyond.json` names only the root package, whose modules are discovered under `modules/`, so nothing under `tests/` enters its compilation. `npm pack` has no `files` rule or `.npmignore` here, so it follows `.gitignore` and includes all of `tests/`, fixtures and the one checked-in `node_modules` fixture directory included, in the archive the command line's acceptance installs; nothing there discovers, compiles or runs them.
- Generated output (`.artifacts/`, `.beyond/`, temporary directories) is never checked in.

## Test organization and source fixtures

These rules are shared by every Beyond repository.

- Contract/unit and integration tests live in `test/` or `tests/`; complete journeys against an installed, composed or exported product live in `acceptance/`, with a README of their own. Harness infrastructure (servers, registries, process lifecycle, copying and substitution) lives in a `support/` directory of the consuming area.
- Applications, packages, modules, documents and assets a test exercises are checked-in files with their real extensions and directory structure under the consuming area's `fixtures/`. Each fixture group has a README naming its purpose, entry modules, the tests that use it, their command, the expected behavior and any intentionally invalid part. A reader inspects the example without running or decoding a generator.
- A harness copies the fixtures it runs or edits to a unique temporary directory, substitutes only explicit values such as versions, ports or origins, and never writes the checked-in files, even when a run fails. Credentials, machine paths and build output are never fixture source.
- Small input values, expected values, protocol payloads and short edits stay inline. Source is generated only when generation is the behavior under test (size or memory stress, combinations, deliberately malformed input); the guide states why, the parameters that reproduce it and how to inspect what was generated.
- Fixtures stay out of the repository's production compilation, discovery and packaging.
- Migrating a test preserves its scenario identities, its positive, negative and recovery cases and its real execution path; an existing failure stays reported as a failure.
