# @beyond-js/packages

For CDN integration, read the [required compiler/resolver contract](docs/cdn-contract.md) and [source evidence](docs/reviews/2026-09-19-cdn-readiness.md). Existing development builders are reusable, but the three-stage CDN pipeline needs additional capabilities.

Packages is the Beyond packaging implementation written in Beyond. It models workspaces, packages, public modules, bundlers, conditional outputs and processors. Packages Core also owns Dev Server/File API, consumed by the standalone CLI, Packages UI and Conduict; the independent CDN consumes shared compiler/artifact capabilities. Packages UI has no backend of its own. Conduict owns machines, working copies and supervisor; Accounts owns people and sign-in, and Projects owns project authorization and Packages enablement. Workspace 2026 is the migration source; its running rules remain in force until coordinated transition.

A workspace groups developing packages, not running consumers. Its packages can serve one or several applications; application boundaries need not match package or workspace boundaries. An application explicitly groups execution targets. The shared persistent application/target catalog required for Core, CLI and UI is not implemented by current preview candidate discovery. Packages expose public modules; their imports, resolved package versions and compiler source inputs are separate graphs. Consumers in supported execution environments load compatible artifacts and keep separate state even when they share a package. Dev Server/CDN delivery is separate from execution and process hosting.

The existing Engine generation compiles Packages implementation modules; modern BEE Node loads their ECMAScript output. Packages then compiles the target packages itself: it discovers their public modules, selects their bundler and conditions, and assembles executable artifacts that keep their public references and can be updated one source file at a time. HTTP delivery, widgets, styles, declarations and supported browser updates are implemented locally with the limits recorded in the guides below; complete hosted integration and acceptance are separate gates.

Beyond also compiles packages into distributable outputs for publication and consumption, including npm packages. This is a core capability alongside development serving. It applies to Packages itself: a compiled distribution must not require Engine to serve its own implementation, while it still runs its Dev Server for the user's project. The current Engine bootstrap and local execution evidence do not establish that independent release path; see [the distribution boundary](docs/local-cli-baseline.md#development-and-distribution).
